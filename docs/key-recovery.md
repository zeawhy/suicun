# 密钥恢复设计（阶段 B）

> 规格 §9、§10、§12 相关。本文如实描述各密钥的丢失后果，不做虚假恢复承诺。

更新时间：2026-10-06（CST）　分支：`antigravity/stage-b`

## 1. 密钥清单

| 密钥 | 用途 | 生成方式 | 存储位置 | 备份/ escrow |
|---|---|---|---|---|
| 数据库密钥（256 位随机） | SQLCipher 加密本地 `suicun.db`（`PRAGMA key`） | `Random.secure()`，首次启动生成 | 平台安全存储（Android Keystore，经 flutter_secure_storage），key 为 `suicun.crypto.dbKey.v1` | **无**。不上传、不 escrow、不进普通备份 |
| 备份密码（用户自选） | 加密备份容器（Argon2id → AES-256-GCM） | 用户在导出时输入，≥8 位 | **不存储**。只存在于用户记忆/密码管理器 | 容器自带 KDF 参数，可凭密码在新设备恢复 |
| 应用锁 PIN | 仅做 UI 解锁，不参与任何密钥派生 | 用户设置，≥4 位 | 安全存储中存盐 + SHA-256（`suicun.applock.pinHash`） | 无 |
| WebDAV 应用密码 | 同步服务认证（阶段 C 才使用） | 坚果云等生成 | 安全存储（`suicun.webdav.*`） | 用户在云盘后台可重新生成 |

## 2. 丢失后果（诚实说明）

### 2.1 数据库密钥丢失

发生场景：清除应用数据、卸载重装且无加密备份、设备恢复出厂、Keystore 因系统升级损坏。

后果：**本地数据库永久不可恢复**。SQLCipher 没有后门；不知道 256 位密钥就无法解密，
暴力破解在计算上不可行。本应用不设"开发者重置入口"（规格 §10 同理适用于本地库）。

用户自救路径（按优先级）：
1. 用之前导出的**加密备份**（需要备份密码）在新安装上恢复 → 数据回来，生成新的数据库密钥。
2. 用之前导出的**明文 JSON 备份**恢复（如果用户做过）→ 数据回来。
3. 已开启 WebDAV 同步（阶段 C）且云端有已同步版本 → 从云端恢复。
4. 以上都没有 → 数据丢失。界面不得暗示"联系客服可找回"。

### 2.2 备份密码丢失

后果：该加密备份容器永久打不开。**没有密码重置**：密码不存储，Argon2id 慢哈希使暴力破解成本高。

用户自救：用另一份备份（如果有多份、记得其中一份的密码）；或从仍能解锁的旧设备重新导出一份新备份。

### 2.3 应用锁 PIN 遗忘

后果分两层，如实区分：
- PIN 只锁 UI，不锁数据库。重装应用可绕过（但重装也会丢数据库密钥，见 2.1）。
- 本阶段**不提供**"PIN 找回"：提供找回即意味着留后门。若用户忘记 PIN 且未设生物识别，
  当前版本只能清除应用数据（= 丢失本地库，见 2.1）后重来。设置页应在启用应用锁时明确提示这一点。

  > 后续可考虑：允许"已通过生物识别解锁的用户重设 PIN"（已实现：生物识别可用时可进设置改 PIN），
  > 这不算后门，因为攻击者没有生物识别就过不了这一关。

### 2.4 WebDAV 密码丢失/泄露

- 丢失：在云盘后台重新生成应用密码，更新随存里的配置即可。**WebDAV 密码不能恢复笔记**
  （规格 §10：笔记由独立的加密密钥保护，阶段 C 实现）。
- 泄露：立即在云盘后台吊销。攻击者拿到 WebDAV 密码只能看到**加密后的**同步对象
  （阶段 C），看不到明文笔记；但可删除云端文件 → 需配合本地备份/回收站恢复。

## 3. 恢复流程（已实现部分）

### 3.1 新设备从加密备份恢复（已实现）

1. 新设备安装 → 设置 → 安全 → 导入加密备份。
2. 选择 `.encrypted.json` 文件 → 输入备份密码。
3. 预览记录数 → 确认 → 单事务导入（失败整体回滚）。
4. 密码错误：明确提示"密码错误或备份被篡改"，不报"文件损坏"误导。

### 3.2 换机（规划，阶段 C）

规格 §11.6：新设备用 WebDAV 凭据 + 加密密码/恢复密钥重建本地库。
本地数据库密钥**不跨设备复制**（规格 §6.1：设备密钥不能直接复制到 iOS；Android 同理，
新设备生成自己的数据库密钥，数据经解密→重新加密入库）。

## 4. 未实现 / 明确不承诺

- ❌ 数据库密钥的云 escrow / 助记词备份：未做。本阶段不提供，用加密备份代替。
- ❌ 忘记备份密码后的恢复：不存在，数学上不可行，不承诺。
- ❌ 已删除的明文数据库文件的"安全擦除"：文件删除后闪存块不保证被覆盖（见 §5）。
- ❌ 防 Root / 防内存取证：超出威胁模型（规格 §9：不承诺抵抗已被恶意软件控制的设备）。

## 5. 已知局限（诚实记录）

1. **明文升级残留**：从明文库 `sqlcipher_export` 迁移后，旧明文文件被删除但闪存物理块
   可能残留可恢复数据。这是 flash 存储的固有特性，应用层无法保证擦除。缓解：
   迁移后立即对新加密库做一次加密备份并建议用户妥善保存；未来版本可提示"旧设备出售前请恢复出厂设置"。
2. **Keystore 可用性**：数据库密钥的 confidentiality 依赖 Android Keystore。
   极少数设备上 Keystore 实现有缺陷；本应用不做额外假设，密钥丢失即按 §2.1 处理。
3. **应用锁 ≠ 数据库加密**：锁屏被绕过（如调试/Root）不等于数据库被解密，
   数据库加密独立有效。反之亦然：数据库加密不代替应用锁的防偷窥作用。
4. **生物识别降级**：应用锁的生物识别允许回退到系统设备凭据（PIN/图案/密码，
   `biometricOnly: false`），这是主流做法，但意味着应用锁的安全性不高于系统锁屏。
   若用户系统锁屏被攻破，应用锁同等失效。数据库加密不受影响（密钥在 Keystore 中，
   与锁屏密码是不同的保护域）。
5. **日志**：代码中禁止记录密钥、密码、Authorization 头。`DatabaseEncryptionError`
   的 message 只含操作描述，不含密钥材料。
