# 轻量个人信息库产品设计与 AI 开发说明

版本：1.2 Android 与 WebDAV 首发版　日期：2026 年 10 月 5 日

本文面向产品负责人和执行开发的 AI Agent。目标是开发一个无需注册、默认离线可用、可以分类并检索保存信息的应用。首发交付 Android 本地优先应用、隐私保护、加密 WebDAV 同步和上架准备，支持新 Android 手机恢复及多台 Android 设备同步；根据使用反馈再考虑 iPhone / iPad（iOS）。macOS 与 Windows 不属于当前范围。文中的技术路线是设计建议，不代表已经实现或经过安全审计。不要把完整同步版本承诺为一两周上线。

## 1 产品定位与边界

暂定工作名：随存。发布名称和包名由负责人最终决定。

一句话定位：保存以后还要找的信息，打开就能记，输入关键词就能找。

典型内容：服务器配置说明、常用网址、软件使用方法、代码片段、项目想法、生活资料。不是密码管理器；密钥和密码继续使用专用密码管理器。本产品不提供实时协作、复杂知识图谱、插件、AI 问答或文档数据库。

设计优先级：数据不丢失 > 搜索准确 > 记录快捷 > 界面简单 > 功能数量。分类和标签均可不填，不要求用户先整理。

## 2 分期交付

| 阶段 | 必须实现 | 暂不实现 | 交付条件 |
|---|---|---|---|
| A 本地核心 | Android、记录编辑、自动保存、分类、可选标签、搜索、收藏、回收站、导入导出、明暗主题 | 云同步、附件、付费 | 完全离线跑通并验证导出恢复 |
| B 隐私保护 | 本地加密存储、应用锁、加密备份、密钥恢复设计 | WebDAV | 数据库及搜索索引无明文，重启可正常恢复 |
| C Android 同步 | WebDAV、端到端加密、换机恢复、冲突保留、同步错误恢复 | iOS、Windows、macOS、Web、其他云盘、自动合并正文 | 两台 Android 设备真实同步、换机恢复及故障测试通过 |
| D 上架准备 | 无障碍、隐私政策、发布构建、商店素材、兼容性验证 | 广告和订阅默认不加入 | 根据提交时官方政策完成检查 |

首发执行顺序为 A → B → C → D。WebDAV 是首发必做能力，用户可选择仅本地使用，也可配置自己的 WebDAV 服务开启同步。第 10、11 节、同步相关数据库表及同步验收项均属于首发范围。备份与导出仍必须可用，独立于同步提供恢复和迁移途径。iOS 留到后续，不影响 Android 多设备同步的实现。

A 阶段允许开发版数据库是明文，但不得对外宣传本地加密。公开版本若以隐私为主要卖点，应完成 B。附件、Markdown 预览可在后续版本独立增加；首版正文为纯文本，能保留代码缩进并打开链接。

| 功能 | 规则 |

## 4 页面结构与交互

### 4.1 首次启动

直接进入空首页，展示“保存以后还要找的信息”和“新建记录”。不出现注册、云盘配置、付费弹窗。分类不预填一堆示例；首次新增分类时可建议“工作、生活、开发、资料”。

### 4.2 首页

顶部为应用名称与设置按钮，下方固定搜索框“搜索保存的信息”。再下方显示筛选条：全部、收藏、用户分类；溢出横向滚动，提供清晰选中状态。

列表项显示标题、正文前两行、分类和修改时间；标签在空间允许时最多展示两个。右下角新建按钮。点记录进入编辑页；长按进入多选，可批量分类、收藏、删除。删除后提供撤销。

搜索时键盘不遮挡结果。没有记录、筛选为空、搜索无结果三种空状态分别给出对应说明；无结果时保留查询并提供清除筛选入口。

### 4.3 编辑页

顶部返回按钮、保存状态、更多菜单。标题输入框接正文大输入区，底部以紧凑行显示分类与标签入口。收藏放在顶部。分类和标签不得弹出阻断正文输入。

输入后 500 ms 防抖自动保存；返回时立即等待最后一次事务落盘。保存状态依次显示“保存中”“已保存”；失败显示“保存失败，重试”，并保留未保存文本。不能在失败时假装成功返回首页。

新记录在第一次产生非空内容时生成持久 ID；全空且从未保存的草稿退出时不创建记录。清空已存在记录属于编辑，不自动删除。应用被系统强杀时最多损失尚未落盘的输入；不要宣称任意情况下零丢失。切后台时尽力提交，但可靠性主要靠持续保存。

链接可点按打开；编辑模式下可通过长按操作。代码仅要求等宽显示选项及缩进保留，不引入复杂代码编辑器。Markdown 默认作为普通文本，不自动执行 HTML。

### 4.4 分类与标签管理

设置中提供分类管理：新增、改名、颜色、删除。名称建议不超过 30 字符；同名不重复。删除后记录转为未分类，并保留正文。同步阶段删除分类使用墓碑，旧设备上传引用时按已删除状态展示为未分类。

标签管理支持改名和删除；删除标签只移除关联，不删除记录。合并同名分类或标签需事务处理关联，不能靠显示层隐藏重复数据。

### 4.5 设置

设置按“外观”“数据”“同步”“安全”“关于”分组。数据包含备份、导入、导出和回收站；同步展示状态、最后成功时间、待上传数、冲突数；安全包含应用锁和加密备份。没有启用的能力不要显示虚假的开关。

### 4.6 同步配置

输入 HTTPS WebDAV 地址、用户名、应用专用密码、同步目录。提供显示密码按钮和“测试连接”。优先建议专用密码，凭据保存在系统安全存储。

首次连接流程：测试读写和必要的条件请求能力 → 检查目录是否已有数据 → 新库创建加密配置或已有库输入加密密码 → 展示即将合并的信息数量 → 同步。已有本地内容不能被远端直接替换。

“关闭同步”停止网络任务，保留本地信息；“移除凭据”另行说明。“更换同步目录”视为加入另一个库，先备份并明确选择合并或另建本地库；禁止默默混合两个库。

## 5 UI 规范

采用 Flutter Material 3，简洁温和，不使用营销式仪表盘。建议浅色背景 #F7F8FA、主文字 #20242C、辅助文字 #687180、主色 #4866D5；深色主题独立定义，不机械反色。

正文基准 16 sp，标题 20–24 sp，辅助信息 12–14 sp；系统放大字体时布局不得裁切。操作触达区至少 48 dp。不能只用颜色区分同步失败、收藏或分类。按钮和输入框有读屏标签，界面支持中文和英文，日期按本地显示，内部时间使用 UTC。

首版只实现 Android 单列布局。未来 iPhone 复用业务与数据逻辑，按平台调整返回、键盘、安全区域和文件选择交互；iPad 多栏布局另行设计。桌面布局和快捷键不属于当前交付。页面状态切换不得导致尚未保存的正文丢失。

## 6 技术架构

建议 Flutter + Dart，业务状态与 UI 分离。本地 SQLite，优先通过 Drift 管理迁移与类型安全查询；数据库驱动和加密方案首版必须先用 Android 最小原型验证，再锁定依赖。不能假定普通 SQLite 包天然支持 SQLCipher 或 FTS5。

分层：presentation 页面 → application 用例 → domain 模型 → infrastructure 数据库、密钥、WebDAV。记录保存直接走本地事务；同步通过持久 outbox 异步执行，不阻塞编辑。

建议目录：lib/features/records、search、categories、settings、sync、security；lib/core/database、storage、errors、localization。共享协议、搜索规则和冲突规则均不依赖 Flutter Widget。

依赖选择要求：查看当前官方文档、维护状态、许可证、Android 支持及可扩展到 iOS 的路径、加密能力、迁移能力；固定经过验证的版本。禁止随意声明某个库“安全”或替换成自己实现的密码算法。

### 6.1 为未来 Apple 平台保留的边界

当前只做 Android，不要求现在准备 Apple 开发账号或构建环境。暂将 Apple 理解为 iPhone / iPad，macOS 另行评估。未来 iOS 开发和签名需具备相应工具链与测试设备，在启动 C 时核对当前官方要求。

避免把 Android 文件绝对路径写进导出格式；文件选择、权限、生物识别、安全存储与后台任务通过平台适配层提供。数据库 schema、稳定 UUID、UTC 时间、备份格式和同步协议保持跨平台，格式头保留版本号。不要将未来客户端绑定到仅 Android 的数据库或密钥插件，也不要因未来可能扩展而现在实现全部平台。

首版无需注册本应用账号、无开发者业务服务器；开启同步需用户自己的 WebDAV 服务凭据。未来 iOS 可连接同一加密库，或导入自包含备份。设备密钥不能直接复制到 iOS；导入后使用新设备本地密钥重新加密。

## 7 数据模型

以下为逻辑模型，开发时需要补充 SQLite 约束和迁移 SQL。

| 表 | 核心字段 | 说明 |
|---|---|---|
| records | id、title、body、category_id、is_favorite、created_at、updated_at、deleted_at、local_seq | UUID 随机 ID；时间仅用于显示；local_seq 是本机递增序号 |
| categories | id、name、color、deleted_at | 默认未分类用 null，不创建固定共享实体 |
| tags | id、name、deleted_at | 同名规范化规则统一 |
| record_tags | record_id、tag_id | 复合唯一约束 |
| revisions | revision_id、entity_type、entity_id、parents_json、encrypted_payload、state | 同步版本及父版本，不可变 |
| outbox | operation_id、revision_id、status、attempt_count、next_retry_at | 本地保存与入队同一事务 |
| remote_receipts | revision_id、remote_path、observed_at | 已确认读取或上传的远端版本 |
| sync_state | vault_id、device_id、protocol_version、last_success_at | 不保存密码 |
| conflicts | id、entity_id、head_revision_ids、resolution_revision_id | 保留冲突分支及解决状态 |

所有 UI 数据和索引同事务更新。启用 foreign_keys，合理使用 WAL；数据库备份必须使用一致性快照机制，不能直接复制正在写入的数据库文件并忽略 WAL。迁移失败不得删除数据库“重建”。

分类、标签、记录都按同步实体处理。主分类是记录字段，标签集合是记录版本快照的一部分；首版同步整条记录快照，避免字段级合并造成隐藏丢失。分类改名应立即反映到搜索；本地整数序号不能用来比较两个设备的先后。

## 8 搜索设计

中文检索是核心验收项，不能把默认 FTS5 unicode61 当作中文分词器。官方 trigram 按三字符建立索引，也不能覆盖一两字查询的全部需求。

第一版用参数化的子串查询作为正确性基线；将查询按空白分成词，多个词采用 AND，每个词可在任意字段匹配。英文大小写不敏感，保留原始文本；规范化缓存用于检索。分类、标签通过关联查询，避免连接重复导致列表重复。

对 LIKE 的 %、_ 和转义字符做字面量转义，所有输入参数绑定。不要将用户输入直接拼接到 SQL 或 FTS MATCH。查询中引号、括号、emoji、中文、URL、代码符号都不报错。

排序优先级：标题完全匹配 → 标题包含 → 标签或分类匹配 → 正文匹配；同等级按收藏和修改时间。显示正文命中位置附近的短片段，并高亮匹配字。单字搜索、两个汉字搜索必须能命中正文中间。

先用 10000 条、平均正文 2 KiB 的样本测试，在记录了型号的中端 Android 真机上以输入结束到结果显示 P95 ≤ 300 ms 为目标；结果分页，每页 50 条。该数字是验收目标，不是现有效果承诺。基线不足时再增加 trigram 候选索引，短查询保留回退；索引始终可重建，且与数据库一同加密。

## 9 本地与同步隐私

威胁范围：降低云盘提供者读取正文、设备普通文件复制、日志泄露和系统备份泄露风险。不承诺抵抗已解锁且被恶意软件控制的设备，也不隐藏网络请求时间、数据大小和云盘目录结构。

同步加密和本地数据库加密是两件事；指纹界面锁也不自动等于数据库加密。

本地库使用经过验证的加密 SQLite 方案，随机数据库密钥存入平台安全存储。搜索索引、WAL、临时文件和备份路径一并验证。首版采用 Android 平台安全存储；未来 iOS 单独接入平台安全存储，不共享设备数据库密钥；如果加密数据库驱动验证失败，停止 B 阶段交付，不虚构安全状态。

应用锁通过生物识别或系统设备凭据；后台超过可配置时长重新锁定。不得自制一个低熵 PIN 后直接用于数据库密钥派生。首次创建数据库或凭据时不上传遥测，不请求通讯录、定位和无关文件权限。

禁止明文正文、标题、URL、WebDAV 密码、密钥、Authorization 头进入日志。错误日志只保留错误码与随机任务 ID。发布前检查平台自动备份和设备迁移规则，排除敏感数据库与凭据；恢复以用户选择的加密备份为主。默认没有分析 SDK 和崩溃上传。

## 10 同步加密协议（Protocol v2）

随存同步协议 v2 采用**多密钥对象模型（Multi-Key Objects）**，消除了对单一共享全局 `header.json` 的条件并发写入门控依赖，完全兼容不支持条件写入（Conditional Write / WebDAV Lock）的网盘服务（如坚果云免费版、Nextcloud 特殊反代配置等）。

每个密钥对象独立存储在 `v2/keys/<key_id>.<variant>.json`。
- **主密钥 $K$**：256 位安全随机生成的对称密钥，不直接由用户密码加密笔记正文。
- **密钥包装槽（Key Slots）**：包含 `password` 槽和 `recovery` 槽。
  - 用户密码经 Argon2id（参数包含版本、内存、迭代数、并行度与 16 字节随机盐）派生包装密钥，以 AES-256-GCM 包装 $K$。槽 AAD 绑定 `suicun/v2/keyslot/<key_id>/<type>`。
  - 恢复密钥槽采用独立高熵随机恢复密钥包装 $K$。
- **对象加密与 AAD**：每个版本对象独立存储于 `v2/objects/<revision_id>.enc`。
  - 采用 AES-256-GCM，96 位随机 nonce，128 位 tag。
  - AAD 强绑定 `suicun/v2/object/<key_id>/<rev_id>/<entity_type>`，杜绝密钥跨对象混用和类型替换攻击。
  - 正文、标题、标签、分类、父版本等所有元数据均在加密载荷中，文件名仅含随机 ID。解密鉴权失败绝不存入本地数据库。

## 11 WebDAV 同步设计（Protocol v2）

### 11.1 存储布局

- 密钥目录：`v2/keys/<key_id>.<variant>.json`（随机 16 进制 key_id 与 variant 命名，无并发重名风险）。
- 对象目录：`v2/objects/<revision_id>.enc`（不可变版本对象，文件名由随机 ID 组成）。
- 历史 v1 目录（兼容与迁移）：根目录 `header.json` 与 `objects/<rev_id>.enc`。迁移后 `header.json` 原子重命名为 `header.json.migrated-backup`。

### 11.2 多密钥并发与活动密钥收敛

- **解密密钥集**：会话内存维护 `MultiKeySession`，所有已解锁的密钥均用于解密（支持历史密钥与多端并发建库密钥）。
- **加密活动密钥（Active Key）**：各端本地确定性选取 `activeKeyId = min(unlockedKeyIds)`（字典序最小）。
  - 目录枚举一致的设备收敛至同一把加密密钥；
  - 短暂网络时序差异导致枚举不一致时短暂使用不同密钥写入，两端由于持有各密钥均能解密互通，枚举完整后自动收敛；
  - 若存在不同密码初始化的密钥，未解锁密钥的对象计入 `lockedKeyCount`，UI 提供输入密码/恢复密钥解锁入口，不丢弃、不损坏。

### 11.3 版本与冲突规则

- 沿用不可变版本对象与父版本 DAG（computeHeads/ancestorsOf）。
- 双端离线或并发编辑同一实体形成多 heads，产生可恢复冲突（Open Conflict）。
- 冲突解决提供“保留本机版本”“保留另一版本”“分别保留”“手动合并”，生成汇合 parents 的新版本。

### 11.4 一次同步过程

1. 获取单实例任务锁，检查网络与解锁状态。
2. **刷新密钥（refreshKeys）**：枚举 `v2/keys/`，下载并解密新密钥合并到会话；未解锁记录为 locked。若无任何已解锁密钥，提示需要密码并暂停同步。
3. **枚举与下载**：枚举 `v2/objects/`，下载未知版本。校验大小上限、版本协议与 envelope；依据 envelope 的 `key_id` 路由解密。未知/未解锁密钥对象标记 skip 且永不入库。
4. **事务落盘**：按 DAG 依赖拓扑排序落盘，更新冲突状态与索引。
5. **上传**：从持久 outbox 取待发版本，使用当前 active key 加密上传至 `v2/objects/<rev>.enc`。支持条件创建则使用 `createOnly`，不支持则普通 PUT 并读回校验。

### 11.5 迁移流程（v1 -> v2）

1. 发现旧版 `header.json` 且无 `v2/keys/` 时，UI 提示“发现旧协议同步库，备份并迁移”。
2. 用户输入密码验证 v1 header（错密码直接报错，不触碰任何远端数据）。
3. 保持同一主密钥 $K$，生成 `origin: v1-migrated` 的 v2 密钥对象写入 `v2/keys/`。
4. 将 `objects/` 下所有不可变对象幂等拷贝至 `v2/objects/`。
5. 调用 WebDAV `MOVE` 方法将 `header.json` 备份为 `header.json.migrated-backup`。

### 11.7 请求、安全与边界

- 强制 HTTPS，严格校验证书。
- 绝不在日志、异常或 UI 中泄露明文、密码、Authorization 头或原始密钥。
- 换机恢复支持凭 WebDAV 凭据 + 密码/恢复密钥在全新设备上完整解密恢复所有历史与多密钥数据。

旧手机突然丢失时，只能恢复已成功上传的数据。最后一次离线编辑或尚未上传内容无法从 WebDAV 找回，界面应如实显示同步状态。同步不是独立备份：误删除会传播，服务文件丢失也可能影响恢复，因此仍保留回收站、版本冲突保护及独立加密导出。

## 12 备份与导入

JSON 备份包含 schema_version、导出时间、记录、分类、标签及关系；同步内部状态与云盘凭据不进入普通备份。提供明文导出用于可迁移性，但执行前说明文件可被读取；默认完整备份推荐加密。

加密备份是自包含的独立容器，包含自己的密码 KDF 参数、包装密钥和鉴权信息；不得只依赖当前设备安全存储，否则换设备无法恢复。

Markdown ZIP 每条记录一个文件，文件名包含 ID 的短片段以避免重复标题覆盖；JSON 元数据保存分类标签。TXT/Markdown 导入默认创建新 ID；完整 JSON 导入可选“作为新记录导入”或“恢复到空库”。已有库不提供未经设计的覆盖恢复。

导入先校验版本、长度、类型、数量限制和关系，在临时区域完整验证；预览新增数和错误，成功后事务提交。ZIP 禁止路径穿越、限制解压后总大小和文件数量。失败回滚，原库保留。恢复到空库时先保存当前加密备份，完成验证后原子切换；新设备从备份加入同步前另做库身份核对。
