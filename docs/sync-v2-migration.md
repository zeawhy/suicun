# 随存 (Suicun) 同步协议 v1 到 v2 迁移指南

本文档面向随存使用者与开发者，详细说明从同步协议 v1（基于单一全局 `header.json`）向 v2（多密钥对象模型）迁移的原理、操作流程、安全性及故障恢复。

---

## 1. 为什么需要升级到 v2

随存同步协议 v1 依赖单一全局 `header.json` 进行库的初始化与密钥管理，并要求 WebDAV 服务端具备**条件创建**（`If-None-Match: *` / 412 Precondition Failed）能力，以防止两个设备首次建库产生密钥冲突。

然而在现实网络环境中：
- 国内常见个人云盘（如坚果云免费版）或部分私有 Nextcloud / NGINX WebDAV 配置不支持条件写入；
- v1 协议在上述服务上会阻断同步初始化，并提示兼容性错误；
- v2 协议改用**多密钥对象模型（Multi-Key Objects）**：每把密钥以独立文件存储于 `v2/keys/<key_id>.<variant>.json`，文件名随机，消除了对服务端条件写入的硬性依赖，两端并发建库两把密钥可以和平共存并自动收敛解密。

---

## 2. 迁移方案设计与安全性保证

迁移过程遵循**零数据丢失、零远端数据破坏、全流程加密验证**原则：

1. **原地不破坏**：
   - 现有的 `objects/` 历史版本对象文件完全保持原样，仅做不可变拷贝到 `v2/objects/`。
   - 验证通过后，将原 `header.json` 重命名为 `header.json.migrated-backup`。
2. **密码防暴力破坏**：
   - 迁移前必须由用户输入正确的同步密码或恢复密钥。
   - 若密码错误，立刻返回 `wrongPasswordOrKey`，**绝不进行任何远端写操作或重命名**。
3. **主密钥继承与连续性**：
   - 迁移生成的 v2 密钥对象保持原主密钥 $K_{vault}$ 不变，标记 `origin: v1-migrated`。
   - 原密码包装槽与恢复密钥槽完整迁移，无需重新生成恢复密钥。
4. **中断幂等与断点续传**：
   - 如果网络在拷贝 `objects/` 过程中意外中断，已拷贝的对象在下一次迁移时直接校验跳过，未完成的对象继续拷贝，直至全部成功。

---

## 3. 用户迁移操作步骤

当在存在 v1 同步库的 WebDAV 目录中配置同步或加入同步时：

1. **自动识别**：
   - 应用检测到远端存在 `header.json` 但尚未建立 `v2/keys/` 目录；
   - 弹出迁移确认对话框：“发现旧版同步库 (v1)”。
2. **确认迁移**：
   - 点击“备份并迁移”；
   - 输入该同步库的原加密密码；
3. **完成迁移**：
   - 客户端自动完成：校验旧密钥 → 生成 v2 密钥 → 拷贝对象 → 备份旧头；
   - 界面提示迁移成功，自动进入正常增量同步。

---

## 4. 其它关联设备迁移提示

- 若用户有多个设备已配置过该 v1 目录：
  - 其中一台设备完成迁移后，`header.json` 已备份为 `header.json.migrated-backup`，远端已呈现标准 v2 结构；
  - 其它设备启动同步时，检测到 `v2/keys/`，会自动识别为 v2 库并进行密钥刷新与正常多端同步。
